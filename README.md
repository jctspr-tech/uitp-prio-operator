# Помощник оператора · прототип УИТП 2.0

Готовое статическое рабочее место: обращение → черновик и решение → основания. Исходные 14 обращений и 11 публичных источников Прио-Внешторгбанка сохранены. V2 добавляет ручной выбор темы и вариант «Тема не определена», локальный поиск, привязку тезисов к материалам, проверку применимости, учебное управление статусами документов, передачу специалисту, оценки и журнал сессии.

Существующий хостинг: [uitp-prio-operator.onrender.com](https://uitp-prio-operator.onrender.com/). Этот комплект содержит локальную версию 2.0; наличие изменений в нём само по себе не подтверждает обновление опубликованного сайта. Развёртывание и проверку хостинга следует фиксировать отдельно. Репозиторий существующего сайта: [jctspr-tech/uitp-prio-operator](https://github.com/jctspr-tech/uitp-prio-operator).

## Что работает

- Тема выбирается оператором до поиска. Вариант «Тема не определена» допускает поиск по всему набору. Готовый пример явно задаёт тему.
- Поиск использует текст локальных материалов, ограничения темы, статуса, учебной роли и срока действия. Подготовленная формулировка выбирается по правилам, а не языковой моделью. Здесь нет LLM, семантических embeddings, серверного RAG или подключения к банку.
- Для каждого тезиса показана ссылка на основание. Публичные фрагменты — пересказы снимка от 09.10.2026, а не проверенные точные цитаты. Действительность банковских условий, владельцы и даты действия не установлены; версия 3.0 указана только у публичного руководства. Отметка «Я проверил ответ» означает заявление оператора о проверке оригинала и применимости, а не автоматическое подтверждение банка.
- Четыре синтетических учебных документа проверяют конфликт, отзыв, будущую редакцию и неутверждённый материал. Их дата сценария фиксирована: **14.10.2026**, чтобы защита не зависела от даты запуска. Даже статус active не допускает учебный документ вне его периода действия.
- Изменение основания сбрасывает проверку и копирование существующего черновика. Для продолжения нужен новый поиск. Правка текста, темы или вопроса также снимает предыдущую проверку.
- В обычном публичном наборе внутреннее направление передачи остаётся неопределённым. Оператор принимает либо отклоняет предложение о передаче и редактирует запрос с вопросом, уточнениями, источниками, выполненными действиями и причиной. Учебный маршрут DEMO-ESC-01 применим только к контрольному набору.
- Сбой и тайм-аут моделируются явно. Вопрос сохраняется, старый черновик очищается, доступна ручная база и запрос специалисту.
- Оценки «Полезно / Не полезно» связаны с ID рекомендации и версиями оснований. Причины включают неверный факт, устаревший источник, неполный ответ и нерелевантный поиск.
- Журнал хранит события и категории в памяти вкладки и экспортируется в JSON. Тексты вопросов, уточнений, черновиков и запросов в него не записываются. После перезагрузки сессия пропадает. Реальные KPI пилота и релевантность AI здесь не измеряются.

## Роли и безопасность демонстрации

Учебные роли: оператор, владелец знаний, аналитик. Владелец может менять модельные статусы; аналитику показан только журнал. Это управление видимостью в браузере, **не настоящая авторизация**. Исходные статические файлы доступны пользователю. Для рабочего решения нужны серверные проверки прав, реальный жизненный цикл утверждения, аудит и согласованные правила защиты данных.

Проверки ввода блокируют распространённые шаблоны номера карты, паспортных данных и секретных кодов, а команды изменить инструкции не рассматриваются как правила. Эти простые проверки не являются полной DLP или защитой LLM. Никакие операции с картой, счётом, CRM или банковским сервером не выполняются.

Лимиты: вопрос — 1200 символов; уточнение — 500; черновик и запрос специалисту — по 5000; ручной поиск базы — 200. Значения выводятся как текст и экранируются. Copy использует текущую проверенную редакцию, блокирует параллельные записи и не переносит поздний результат буфера на новую рекомендацию. Если браузер не разрешил запись, текст выделяется для Ctrl+C / ⌘C.

## Локальный запуск

Из каталога `operator-web`:

```sh
python3 -m http.server 8000 --directory dist
```

Откройте [localhost:8000](http://localhost:8000/). Сборщик, база и ключи API не нужны. Для HTTPS-хостинга подходят прежние Render Static Site и каталог публикации `dist/`. Содержимое `render.yaml` — предлагаемый шаблон; применённые заголовки и статус автопубликации необходимо проверять на существующем сервисе отдельно.

## Файлы и проверки

| Файл | Назначение |
|---|---|
| `dist/index.html` | Доступное рабочее место, вкладки, диалоги |
| `dist/styles.css` | Три области, адаптивность, клавиатурный фокус |
| `dist/knowledge.js` | Публичный снимок, 14 примеров, учебный контрольный набор |
| `dist/app.js` | Локальный поиск, правила, жизненный цикл, журнал и интерфейс |
| `render.yaml` | Существующий шаблон Static Site |

Синтаксис:

```sh
node --check dist/app.js
node --check dist/knowledge.js
```

Новый Test Plan, 20 тест-кейсов, результаты фактических проверок, скриншоты, методика AI и сценарий защиты находятся в соседнем комплекте `outputs/masha-v2/`. Прежний отчёт части 2 и результаты старого harness относятся к прежней версии. Они не подтверждают v2 и не используются как доказательство качества AI ≥90%.

## Контрольный API

`window.OperatorDemo` предоставляет те же локальные действия для независимых logic/unit проверок: `getState`, `prepare(question, topic, failure)`, `clarify`, `setRole`, `setSourceStatus`, `verify`, `updateDraft`, `routeDecision`, `handoff`, `updateHandoff`, `feedback`, `loadDemo`, `reset`, `exportLog`, `copy`, `openSource`, `openMaterials`, `retrieve`, `restoreSources`.

Тема `unknown` означает явно выбранный вариант «Тема не определена». Названия контрольных сценариев: `answer`, `clarify`, `insufficient`, `conflict`, `revoked`, `future`, `error`, `timeout`, `control` (синоним `answer-control`). Статусы: `active`, `revoked`, `future`, `draft`, `restricted`, `expired`. `setSourceStatus` и `restoreSources` требуют модельную роль `owner`; этот API не создаёт реальных прав доступа. `routeDecision` принимает `accepted` или `rejected`. `exportLog` возвращает объект JSON без скачивания; кнопка интерфейса скачивает его локально.
