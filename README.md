# Переносимый сайт помощника оператора

Сайт опубликован: [открыть помощник оператора](https://uitp-prio-operator.onrender.com/). Исходники: [jctspr-tech/uitp-prio-operator](https://github.com/jctspr-tech/uitp-prio-operator). Сервис создан напрямую как Render Static Site; обновления ветки `main` автоматически публикуются. Проверенные четыре файла интерфейса соответствуют версии `f5af4353c37e426124a6f889ba77350409ae2316`. Последующая правка README не меняет эти файлы.

Обычный статический сайт на HTML, CSS и JavaScript. Для работы достаточно четырёх файлов в `dist/`. Создание ответа, уточнение, просмотр источника, правка и копирование выполняются в браузере. Серверная программа, сборщик, база данных, аккаунт пользователя и ключи API не нужны.

Это исследовательский прототип с подготовленными ответами по публичным материалам банка. Он не подключён к системам банка и не отправляет обращения. Содержимое вопроса и правки сохраняются только в памяти открытой вкладки. Загрузка сайта обращается к хостингу за статическими файлами; внешние официальные источники открывает сам оператор.

## Файлы

| Файл | Назначение |
|---|---|
| `dist/index.html` | Страница рабочего места |
| `dist/styles.css` | Оформление и адаптивность |
| `dist/knowledge.js` | Снимок публичных материалов: 11 источников, 14 примеров |
| `dist/app.js` | Логика сценариев, проверки источника, правки и копирования |
| `render.yaml` | Настройки Render Static Site и HTTP-заголовков |

В обычном браузере сайт работает самостоятельно. Дополнительные действия через `document.modelContext`, если такой API предоставлен браузером, регистрируются условно. Отсутствие этого API не мешает работе кнопок и форм.

## Локальный запуск

Откройте терминал в каталоге `operator-web` и выполните:

```sh
python3 -m http.server 8000 --directory dist
```

Откройте `http://localhost:8000/`. Загрузка через HTTP localhost удобнее прямого открытия HTML-файла: браузер обычно предоставляет Clipboard API в безопасном контексте localhost. Доступ к системному буферу может быть запрещён настройками браузера; тогда текст выделяется для Ctrl+C / ⌘C.

## Render: публикация как отдельного сайта

1. Создайте отдельный Git-репозиторий и поместите содержимое каталога `operator-web` в его корень: `dist/`, `README.md`, `render.yaml`.
2. В Render выберите создание Blueprint из этого репозитория. По умолчанию Render ищет `render.yaml` в корне.
3. Проверьте, что создаётся **Static Site**, `runtime: static`, каталог публикации — `dist`, команда проверки — `node --check dist/app.js && node --check dist/knowledge.js`.
4. Опубликуйте сайт и откройте выданный HTTPS-адрес. Проверка синтаксиса выполняется перед публикацией; отдельная сборка не требуется.
5. Выполните браузерные проверки после публикации: загрузку четырёх файлов, ответ, уточнение, источник, правку и реальную контрольную вставку скопированного текста. Убедитесь, что HTTP-заголовки из Blueprint применились.

Если используете **New → Static Site** вручную, укажите те же build command и publish directory; добавьте заголовки из `render.yaml` в настройки Headers. При размещении папки внутри большого репозитория установите Root Directory в `outputs/operator-web`; при Blueprint настройте соответствующий `rootDir` либо используйте отдельный репозиторий, как описано выше.

Static Site не имеет compute plan: в Blueprint не нужно добавлять `plan: free` и `startCommand`. У Render есть бесплатный уровень статических сайтов; трафик и минуты сборки учитываются в лимитах рабочего пространства. Проверьте текущие лимиты своего аккаунта. В предлагаемом шаблоне `render.yaml` автоматическая публикация отключена через `autoDeployTrigger: off`. Этот шаблон не использовался для создания текущего сервиса: у опубликованного сайта автопубликация `main` включена.

Основание конфигурации: [Render — Static Sites](https://render.com/docs/static-sites) и [Blueprint YAML Reference](https://render.com/docs/blueprint-spec), проверены 11.10.2026. Перед использованием конфигурацию можно проверить командой `render blueprints validate render.yaml` (Render CLI 2.7+).

`render.yaml` прошёл локальную проверку по официальной JSON Schema Render 11.10.2026. Эта проверка подтверждает структуру предлагаемой конфигурации. У фактически опубликованного сервиса подтверждены HTTP 200, HSTS, `X-Content-Type-Options: nosniff`, совпадение четырёх файлов и три основные ветки. Пользовательские CSP, X-Frame-Options и Referrer-Policy из Blueprint в этот сервис не переносились и не объявляются действующими.

## Ограничения текущего прототипа

- Подготовленные тексты выбирает детерминированный классификатор. Здесь нет языковой модели, поиска по внутренним документам или обещания ответа на произвольный вопрос.
- Дата `09.10.2026` означает дату исследования публичных материалов. Действующий тариф и версию сервиса оператор сверяет с оригиналом.
- Явное подтверждение источника разрешает копирование ответа. Правка сбрасывает эту отметку.
- Поля ограничены 1200 символами для вопроса, 500 для уточнения и 5000 для ответа. Кроме HTML `maxlength`, обработчики ввода обрезают превышение перед обновлением состояния и счётчика.
- При задержке Clipboard API через 1,6 секунды доступно ручное выделение. Повторная автоматическая запись заблокирована, пока предыдущая запись действительно не завершится: браузер не предоставляет её отмену.
- В предлагаемом Blueprint CSP предусматривает запрет исходящих запросов страницы (`connect-src 'none'`); в текущем сервисе этот пользовательский заголовок не применён. Во время проверенных действий журнал Network не показал передачи обращения. Для будущего серверного API политика заголовков согласуется вместе с архитектурой и разрешёнными источниками.

## Neon и дальнейшее развитие

Для этой статической версии Neon не требуется. Подключение базы появляется только при отдельной потребности хранить материалы, историю или данные пользователей. Тогда нужен серверный API с правилами доступа; секреты и строку подключения нельзя размещать в `dist/`. В текущий пакет такой сервер, база и авторизация не добавлены.

## Что проверено

В проекте `outputs/part2/regression-test.mjs` запускает полезные регрессионные проверки **logic/unit** с Node VM и имитацией DOM/Clipboard. Команда из корня проекта:

```sh
node outputs/part2/regression-test.mjs
```

Результаты сохраняются в `outputs/part2/regression-results.json`. Эти проверки не подтверждают внешний вид, фокус, клавиатуру, реальный системный буфер, сеть или публикацию. Браузерные проверки и их фактические результаты оформляются отдельно.

В распакованном комплекте части 2 каталог `outputs` опущен: из корня комплекта выполните `node part2/regression-test.mjs`. Итоговый отчёт находится в `part2/testing-report.md`: 20 успешных интерфейсных кейсов, 109 основных UI-наблюдений и 2 дополнительные записи внешних переходов. Показатель релевантности AI не измерен; используется подготовленный набор ответов.
